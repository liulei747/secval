# 只读安全审计（当前原型）

本文说明当前 Web 审计板块已实现的用法和边界。实现进度与验收记录见
同目录的 [audit-implementation-status.md](audit-implementation-status.md)。

## 审计做什么

协作审计由一个主 Agent 加最多三个子 Agent（基线、架构、专项调查员）并行完成：
每个 Agent 独立调用只读取证工具（源码读取、精确字面搜索、混合搜索、Neo4j 声明
关系、Joern 调用/数据流、框架入口识别），所有结论必须引用固定源码快照中的证据。
模型不能执行代码、不能提交任意 Cypher/CPGQL、不能读取未授权配置。

识别到的漏洞候选要经过两层验证：主调查记录候选详情后，由独立上下文的证据包复核
确认（复核不继承调查对话，降低锚定）；复核通过且指纹与详情一致时，候选才提升为
正式发现（状态仍为 static_supported_needs_review，等待人工复核）。

## 使用方式

浏览器打开 <http://127.0.0.1:8000/audit>：选择仓库/快照、填写目标与可选上下文、
设置预算、勾选外发同意后开始调查。页面会显示子 Agent 进度、报告收口状态
（未提交/部分报告/已登记检查项收口）和未收口原因；续跑复用同一组预算输入。

主要接口：

- POST /api/audits：创建审计（需 allow_remote_code=true 才会把源码发送给模型）；
- GET /api/audits/{id}：任务状态、子 Agent 进度、调用统计；
- POST /api/audits/{id}/cancel：请求取消（已发送的模型请求不能撤回）；
- POST /api/audits/{id}/resume：从检查点续跑，父任务保持不变；
- GET /api/audits/{id}/report：导出报告（含源码，勿公开分享）；
- GET /api/audit-settings：查看当前模型配置（不含地址和密钥）。

## 预算与长任务

调用（1-300 次）和时长（30-3600 秒）预算各阶段共享。预算在请求边界检查：
耗尽后任务收口为 budget_exhausted，已落盘的检查点、证据和子任务结果都保留；
通过 /resume 建立子任务可继续，父报告永不修改，续跑链可跨多代。
被预算保留暂停的子任务会在主调查提交报告前自动恢复一次完成收尾。

## 报告语义

- not_submitted：尚未提交报告；
- partial_report：已提交但有未收口项（未接续调查、未复核候选、未登记文件审阅等）；
- recorded_checks_closed：已登记检查项收口——这只表示登记的工作完成，
  不等于完整安全审计，报告始终声明 completeSecurityAudit=false。

## 当前限制

- 仅支持 Java 和 Python；框架入口识别覆盖 Spring/JAX-RS/FastAPI/Flask/Django
  注解与程序式路由，以及过滤器/拦截器/中间件安全边界；
- 仅静态分析，未动态复现；发现需人工复核，不代表项目安全；
- 单机单用户原型：跨主机排队、认证和多用户隔离未实现，不得公开部署；
- 独立复核使用同一模型的独立上下文，不是不同供应商，也不是动态验证。
