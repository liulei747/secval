# 合成审计效果验收

这些样例验证模型推理质量，不用于证明真实项目已完整审计。不得把脚本预设结论或格式测试当作模型效果。

三个独立任务使用同一审计目标：订单读取的跨用户访问控制。`cases.py` 包含完整合成代码、明确部署前提和独立期望答案；只能将 `model_input()` 返回的资料发送给模型，不能发送整个样例对象或文件源码（其中含答案）。

| 样例 | 预期 | 验收关注点 |
| --- | --- | --- |
| case-a | 静态支持缺少所有权控制 | 用户可控 ID → 查询 → 返回私有地址，定位返回前缺失的控制 |
| case-b | 反证否定该越权假设 | 发现返回前的所有者校验，不因危险模式或读取顺序误报 |
| case-c | 证据不足 | 主动追查策略实现；缺失实现不能被解释为无控制或已安全 |

执行要求：

1. 使用各自独立的仓库/版本、快照、索引及任务上下文，不共享其他样例的结论。
2. 模型必须使用正常取证工具，不能直接拿预期结论生成报告。检索命中不计为读取证据。
3. 每例最多20次模型调用，三例总上限60次；网络失败也计入预算，不自动重试。调用前须取得费用及凭据使用授权。
4. 保留完整任务报告、调用计数和停止原因。失败、预算耗尽、没有相关调查结论均归为未完成，不能把“没发现”计为负样例通过。
5. 人工核对来源、路径、关键行、攻击者权限、数据流、反证和独立验证。case-a仅有宽泛假设不算通过；case-b必须确实读到并解释防护；case-c须点明未提供的策略实现。
6. 三例结果分开记录，既报正确结果，也报误报、漏报、证据不足及流程失败。单次三样例不能推断总体准确率。
